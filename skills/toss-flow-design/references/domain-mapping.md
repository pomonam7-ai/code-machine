# 분야별 흐름 치환

다음은 토스의 금융 기능을 복제하는 대신 핵심 대상·행동·상태를 해당 업종으로 바꾸는 예시다. 숫자·실적·가짜 고객을 실제 데이터처럼 채우지 않는다.

| --- | --- | --- | --- |
| 영업·CRM / 반복 업무 | 고객·마지막 상담·다음 할 일 | 고객 → 상담 메모 → 연락 초안 → 검토 → 공유 → 연락 이력 | 초안 / 복사됨 / 외부 앱 열림 / 실제 발송 기록 |
| 예약 / 빠른 실행 | 서비스·일정·예약 가능 여부 | 서비스 → 날짜·시간 → 연락 정보 → 조건 확인 → 예약 요청 | 작성 중 / 요청 접수 / 예약 확정 / 취소 요청 / 취소 완료 |
| 쇼핑 / 비교·탐색 | 상품·가격·옵션·배송 조건 | 검색·카테고리 → 비교·상세 → 옵션 → 장바구니·구매 → 결과 | 장바구니 추가 / 주문 접수 / 결제 완료 / 배송 중 |
| 교육 / 학습 재개 | 과정·현재 진도·다음 학습 | 이어서 학습 → 콘텐츠 → 활동·퀴즈 → 결과 → 다음 학습 | 열람 / 진도 저장 / 제출 / 채점 완료 |

## 치환 예시: 예약 서비스

홈에는 ‘다가오는 예약 + 변경·상세’를 두고 신규 사용자는 서비스 선택을 먼저 보게 한다. 방문 장소·시간처럼 함께 비교해야 하는 정보는 같은 화면에 둔다. 확인 화면에서는 일정·대상·비용·취소 조건을 확인하게 한다. 운영자 승인이 필요한 서비스는 ‘예약 완료’ 대신 ‘예약 요청을 접수했어요’라고 표시하고 확정 여부를 별도로 보여준다.

## 치환 예시: 교육 서비스

재방문 사용자에게는 검색보다 ‘이어서 학습’을 우선한다. 처음 방문한 사용자는 과정 탐색과 비교가 필요하다. 퀴즈 전체를 항상 한 문제씩 나누지 말고 문항 간 비교·복습 요구를 고려한다. 단순히 콘텐츠를 열었다는 이유로 학습 완료 처리하지 않는다.

## 치환 예시: 현장 점검 앱

목록에 대상·점검 기한·상태를 보여주고 행을 눌러 진행 중인 점검을 복원한다. 네트워크가 불안정한 현장이라면 ‘기기에 저장’과 ‘서버 접수’를 구분한다. 업로드 실패 시 전체 입력을 다시 요구하지 않고 실패 항목에서 이어서 재시도할 수 있게 한다.

## 선택 기준

- 상위 기능이 적으면 하단 탭 없이 한 화면과 기록 화면만으로 충분할 수 있다.
- 본질이 탐색이면 검색·필터·비교가 주요 행동이며 단일 순서로 강제하지 않는다.
- 짧고 되돌릴 수 있는 저장은 인라인 피드백으로 끝낼 수 있다.
- 실행 결과가 즉시 확정되지 않으면 대기 상태와 다음 확인 방법을 제시한다.
- 긴 입력은 관련 항목을 묶고 저장·복귀를 지원한다. 단계 수를 줄이는 것보다 손실과 혼동을 줄이는 것이 중요할 수 있다.
