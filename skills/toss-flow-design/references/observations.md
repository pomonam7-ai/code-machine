# 토스 실앱에서 관찰한 근거

2026-11-04 갤럭시 S25 / Android 17의 실제 토스 앱을 Mobile MCP로 탐색했다. 앱 버전은 별도로 확인하지 않았다. 특정 사용자·로그인 상태에서의 관찰이며 모든 사용자나 이후 버전의 고정 명세가 아니다. 이 파일은 개인 금융 정보와 기기 식별자를 포함하지 않는다.

| 직접 확인한 내용 | 일반화 가능한 설계 판단 | 적용의 경계 |
| --- | --- | --- |
| 홈의 계좌 행에 요약 정보와 송금 버튼이 함께 있음 | 대상 목록에서 맥락과 바로 할 행동 결합 | 모든 행에 버튼을 추가하는 규칙은 아님 |
| 하단 홈·혜택·쇼핑·증권·전체 | 동등한 상위 영역과 세부 작업의 계층 분리 | 다섯 탭·전체 메뉴를 모든 제품에 강제하지 않음 |
| 전체 상단에 검색·고객센터·설정 | 빈도·목적에 따라 진입점 배치 | 단순한 서비스에는 전체 메뉴가 필요 없을 수 있음 |
| 전체 → 검색 → 송금 입력 → 추천 검색어 → 결과 분류 → 송금 메뉴 | 서비스가 많으면 검색 결과를 의미 있는 범주로 구분 | 이미 아는 주 과업에 불필요한 검색 단계를 추가하지 않음 |
| 서비스 이용 후 최근 서비스 항목이 갱신됨 | 반복 작업의 재진입을 빠르게 함 | 이력이 없는 첫 사용 상태도 설계해야 함 |
| 송금 메뉴에 송금하기·자동이체·더치페이 등 별도 진입점 | 행동 방식이 다르면 먼저 목적을 명확히 함 | 단일 기능이면 허브 화면을 추가하지 않아도 됨 |
| 송금하기 → ‘어디로 보낼까요?’ → 계좌·카카오톡·연락처 탭 | 한 질문에 집중하고 대안 입력 방식을 분리 | 채널별 실제 구현·권한은 별도로 판단 |
| 계좌 입력과 내 계좌·최근 보낸 계좌를 함께 제시 | 신규 입력과 반복 선택 모두 지원 | 고객 정보 노출·보관 범위는 제품에 맞게 정함 |
| 전체 → 설정 → 화면 테마·진동 상세 | 반복되는 환경 설정을 주 과업에서 분리 | 사용자가 작업 중 필요한 옵션까지 숨기지 않음 |
| 혜택은 미션 행별 방문 버튼, 쇼핑은 검색·카테고리·상품 중심 | 목적에 따라 정보 밀도와 탐색 방식을 다르게 설계 | 업무 앱에 광고·리워드·쇼핑 구조를 그대로 이식하지 않음 |
| 밝은 회색 바탕·흰 카드·아이콘/텍스트/오른쪽 행동의 행 구성 | 관련 정보를 묶고 위계를 일관되게 표현 | 공식 색상·간격·서체 토큰을 계측한 결과는 아님 |

## 검증하지 않은 부분

- 가입·약관·최초 계좌 연결 전체 과정.
- 수취인 지정 이후 금액 입력·출금계좌 선택·인증·송금 완료의 실제 화면 순서.
- 수취 화면의 카카오톡·연락처 탭 내부 전체 동선.
- 상품 신청·결제·거래 완료와 오류 분기.
- 증권 내부: 보안 경고가 표시되어 탐색을 중단했으며 원인은 확정하지 않음.

따라서 검토·완료·재시도·상태 복원에 대한 스킬 지침은 제품을 완성하기 위한 일반 설계 권고다. 위 미확인 구간을 토스에서 관찰한 사실로 제시하지 않는다.

과거 분석 근거만 사용할 때 매번 다시 탐색할 필요는 없다. 최신 토스 화면·정확한 공식 값이 요구되면 현재 자료나 승인된 실제 화면으로 새롭게 확인한다.
